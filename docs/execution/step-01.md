# تقرير تنفيذ الخطوة 01: معالجة موانع الأمان العاجلة

## 1. ملخص تنفيذي
تم تنفيذ إجراءات تأمين الوضع الحالي لمستودع `jira-nexus` قبل أي توسع برمجي أو معماري. ركزت الخطوة على استئصال تسريبات الأسرار الصريحة، وتأمين مسار المصادقة والجلسات ضد إعادة التوليد والتفويض الزائف، وضمان ظهور أخطاء الصلاحيات بأمان تام.

## 3. القرارات المعمارية والهندسية (Architectural Decisions)
1. **استخدام آلية `sync: false` في `render.yaml`**: إبلاغ محرك النشر Render بأن القيم السرية تُدار حصرياً عبر لوحة التحكم السحابية المأمونة ولن يتم تضمينها في الكود البرمجي مطلقاً.
2. **فصل حالة الجلسة الصالحة عن التوقيع (Stateless Signature vs Stateful Revocation)**: التوقيع الرقمي HMAC للرمز يثبت أصل الرمز فقط، بينما قرار الصلاحية الفعلي مرتبط بوجود سجل الجلسة في قاعدة البيانات ونشاط المستخدم (`active = 1`). عند تسجيل الخروج يُحذف السجل نهائياً ويُمنع أي استرجاع.
3. **Fail-Fast في الإنتاج**: أي محاولة لتشغيل خادم Node.js أو .NET في وضع `Production` بدون مفتاح تشفير حقيقي أو بسلاسل اتصال افتراضية تقابل بفشل إقلاع فوري (`Fatal Security Error`).
4. **الشفافية في التعامل مع أخطاء واجهة المستخدم (Fail-Safe UI)**: التوقف عن ابتلاع الأخطاء السحابية؛ إذا تعذر تحميل الصلاحيات أو حفظها، تظهر الواجهة حالة الخطأ بوضوح ولا تمنح المستخدم وصولاً فائقاً ولا تدّعي نجاح الحفظ.

## 4. سجل إدارة المخاطر (Risk Management)
- **مخاطر استمرار الاعتمادات المسربة قيد العمل**: المفاتيح القديمة لـ Supabase وMirat التي وُجدت سابقاً في السجل العام يجب اعتبارها مخترقة بالكامل حتى يتم تدويرها خارجياً من قبل المالك.
- **مخاطر جلسات المستخدمين القديمة**: عند تدوير `SESSION_SECRET`، سيُطلب من جميع المستخدمين المسجلين تسجيل الدخول مجدداً، وهو سلوك مرغوب ومطلوب أمنياً.

---

## 5. خطة الترحيل والتراجع (Migration & Rollback)
- **الترحيل (Migration)**:
  1. ضبط المتغير `SESSION_SECRET` بقيمة عشوائية قوية في بيئة التشغيل.
  2. ضبط `DATABASE_URL` و `ConnectionStrings__DefaultConnection` عبر لوحة تحكم الخادم.
  3. تشغيل `npm run check:secrets` في بيئة CI/CD كبوابة مانعة للدمج.
- **التراجع (Rollback)**:
  - التغييرات برمجية فقط ولا تتضمن ترحيلات لقواعد البيانات. في حال حدوث أي طارئ يمكن استرجاع ملفات المصادقة السابقة بواسطة Git مع الاحتفاظ بالأسرار خارج المستودع.

## 6. دليل تشغيلي لتدوير الاعتمادات لدى المالك (Credential Rotation Runbook)
> [!IMPORTANT]
> يجب على مالك المشروع تنفيذ هذه الخطوات على وجه السرعة من لوحات التحكم الرسمية دون مشاركة أو طباعة القيم السرية في غرف الدردشة أو المستودع:

### أولاً: تدوير كلمة مرور قاعدة بيانات Supabase
1. الدخول إلى لوحة تحكم Supabase للمشروع المعني.
2. الانتقال إلى: **Project Settings** → **Database**.
3. التمرير إلى **Database Password** والضغط على **Reset Password**.
4. توليد كلمة مرور معقدة وتخزينها في مدير كلمات المرور المؤسسي.
5. تحديث متغير البيئة `ConnectionStrings__DefaultConnection` على Render بالرابط الجديد.

### ثانياً: تدوير مفاتيح Mirat Error Monitoring
1. الدخول إلى منصة مراقبة Mirat.
2. حذف الرموز القديمة (Tokens/DSNs) الخاصة بالخدمات الثلاث (node-api, web, dotnet-api).
3. إنشاء مشروعات أو DSNs جديدة لكل بيئة عمل.
4. إدخال القيم الجديدة مباشرة كمتغيرات سرية في منصة الاستضافة (Render Dashboard).

### ثالثاً: تعيين مفتاح توقيع جلسات Node.js
1. توليد مفتاح سري عشوائي بطول لا يقل عن 64 رمزاً:
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
2. تعيين المفتاح الناتج في بيئة Render تحت اسم `SESSION_SECRET`.
