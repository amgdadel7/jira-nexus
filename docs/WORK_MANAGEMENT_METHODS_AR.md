# اختيار أسلوب إدارة العمل — مواصفة وخطة تنفيذ

الحالة: مخطط، غير منفذ. تاريخ: 20 أكتوبر 2026.

## الهدف

اختيار أسلوب المشروع عند إنشائه، ثم تهيئة السلوك والمشاهد والقواعد والتقارير فعلياً، لا حفظ اسم فقط. Agile مظلة مبادئ؛ Scrum إطار وKanban أسلوب إدارة تدفق. تستخدم الواجهة عنوان «أسلوب إدارة العمل» لتجنب مساواة المصطلحات.

## كتالوج الخيارات

| الخيار | الإعدادات والسلوك | التقارير المناسبة |
|---|---|---|
| Scrum | Backlog وسبرنتات وهدف وتقدير وسياسة إنهاء وترحيل عمل | Burndown وVelocity والعمل المرحل، عند توفر تاريخ كافٍ |
| Kanban | تدفق مستمر وحدود WIP وسياسات انتقال، مع فصل حدود التحذير عن المنع | WIP وThroughput وCycle Time وعمر العمل |
| Waterfall | مراحل وتسليمات وخط أساس وتبعيات وبوابات اعتماد | تقدم مراحل وانحراف عن خط الأساس وحالة تسليم واعتماد |
| Hybrid | مراحل المشروع مع تنفيذ Scrum أو Kanban داخل مسارات محددة | تقدم المراحل وتقارير كل مسار دون خلط وحدات القياس |
| Simple | قائمة ولوحة ومواعيد ومسؤوليات دون فرض سبرنتات أو موافقات | أعمال مستحقة ومنجزة ومتأخرة |
| Custom | تركيب قدرات معتمدة وقواعد توافق واضحة | تقارير تنطبق على القدرات والبيانات المتاحة فقط |

تفعيل قالب ليس إثبات التزام الفريق بإطار Scrum كاملاً أو اعتماد مهني لمنهجية. القالب نقطة بداية قابلة للتعديل بإصدار جديد، لا نسخة بيانات منفصلة.

## مستويان للإعداد

- المشروع: الأسلوب العام والمراحل والتسليمات والسياسات المشتركة.
- مسار التنفيذ: أسلوب الفريق داخل المشروع عند الحاجة، مع حدود واضحة وملكية للعناصر.
- لكل عنصر مسار تنفيذ أساسي واحد في اللحظة نفسها؛ الاشتراك في مشاهد متعددة لا يكرر العنصر أو احتسابه.
- inheritance صريح: يحدد أي إعداد يرث من المشروع وأي override مسموح. سياسة المشروع الأمنية أو بوابة اعتماد إلزامية لا يتجاوزها override.
- إسناد العنصر إلى سبرنت يجب أن يتوافق مع مشروعه ومساره؛ النقل عبر المسارات عملية تحقق مستقلة تحفظ التاريخ.

## نموذج بيانات مرشح — ليس DDL معتمداً

- تعريف أسلوب ثابت المعرف، محلي الاسم، وله إصدارات immutable بعد النشر.
- ProjectMethodAssignment: المشروع وإصدار الإعداد ونطاق سريانه والوقت والفاعل.
- ExecutionTrack: المشروع والفريق والأسلوب الفعال والقدرات الموروثة/المخصصة.
- CapabilityConfiguration: إعدادات مثل sprints وWIP وstages وapprovals وestimation والتقارير المدعومة.
- MethodChangePlan: الإصدار المصدر والهدف ونسخة المشروع عند المعاينة وmapping وقرارات معالجة التعارضات والحالة.
- سجل تدقيق وأحداث تغيير؛ قيود مفاتيح مركبة أو ما يعادلها لمنع مراجع عبر المؤسسات.

يُحسم النموذج بعد فحص الكود في 10. لا جدول جديد يكرر workflow أو custom fields إذا أمكن ربطهما بإصدارات صحيحة.

## رحلة إنشاء المشروع

1. اختيار نوع الفريق والهدف، ثم عرض الأساليب مع شرح وفروق؛ أي توصية قابلة للتجاوز.
2. معاينة ما سيفعل: حالات ومشاهد وتقدير وسبرنتات أو مراحل وموافقات.
3. إظهار القدرات غير المنفذة أو غير المتاحة بالخطة كغير متاحة؛ لا إنشاؤها شكلياً.
4. إنشاء المشروع وإعداداته بمعاملة أو آلية تعافٍ موثقة ومفتاح idempotency.
5. شرح الإعداد الفعّال، مع تهيئة اختيارية لمسارات الفرق في الإصدار الداعم لها.

## تغيير الأسلوب في مشروع قائم

صلاحية مستقلة لتعديل إعداد إدارة العمل، وإنفاذ على الخادم، وسجل ومعاينة قبل التطبيق.

### معاينة الأثر

- مطابقة حالات وعلاقات وحقول ومراحل؛ لا mapping مبني على الاسم وحده.
- معالجة السبرنت النشط: منع التحويل أو طلب إنهائه/إلغائه وفق عقد صريح. لا حذف أو إغلاق آلي صامت.
- مطابقة التقديرات دون افتراض أن نقطة قصة تساوي ساعات.
- مراجعة قواعد الأتمتة والنماذج والموافقات وواجهات التكامل والتقارير المتأثرة.
- عرض عدد الموارد المتأثرة ضمن الصلاحية وعدم كشف بيانات مخفية.

### تطبيق آمن

- خطة مرتبطة بإصدار المصدر والهدف ومراجعة إعداد المشروع؛ ترفض الخطة القديمة إذا تغيرت البيانات المؤثرة.
- إعادة فحص الهوية والصلاحيات وتوافق البيانات وقت التنفيذ، مع منع تغييرات متعارضة أو إعادة التحقق داخل المعاملة.
- idempotency ومنع تطبيق خطة مرتين؛ تغيير ذري أو job قابل للاستئناف مع حالات ومصالحة معلنة عند كبر الحجم.
- لا حذف للتاريخ؛ التقارير تحفظ الفترة والإعداد الساري آنذاك، ولا تعيد تفسير الماضي تلقائياً.
- تراجع قبل الالتزام حيث أمكن، وبعده تغيير تعويضي بإصدار جديد؛ لا وعد بإلغاء موافقات أو رسائل خارجية سبق تنفيذها.

## مصفوفة قبول أساسية

| الرمز | السيناريو | النتيجة المطلوبة |
|---|---|---|
| M01 | إنشاء Scrum وKanban وSimple | سلوك ومشاهد وقواعد مختلفة من النواة نفسها |
| M02 | Waterfall/Hybrid قبل اكتمال محرك المراحل | الخيار غير متاح مع شرح، لا مشروع شكلي |
| M03 | إنشاء/إعادة طلب الإنشاء | مشروع واحد وإعداد واحد دون موارد مكررة |
| M04 | سحب صلاحية قبل تطبيق تغيير | رفض دون تغيير أو كشف تفاصيل موارد محظورة |
| M05 | مشروع أو مسار من مؤسسة أخرى | رفض في القراءة والمعاينة والتطبيق والأحداث |
| M06 | Scrum إلى Kanban مع سبرنت نشط | منع أو معالجة صريحة مع حفظ السبرنت وتاريخه |
| M07 | تعديل إعداد بعد المعاينة | رفض الخطة القديمة وإعادة المعاينة |
| M08 | تكرار تطبيق/تعطل منتصف التطبيق | لا ازدواج ولا حالة مجهولة؛ تعافٍ مثبت |
| M09 | مشروع Hybrid بفريق Scrum وآخر Kanban | لا ازدواج عناصر أو تجاوز بوابات اعتماد |
| M10 | تغيير أسلوب ثم قراءة تقرير قديم | تعريف المؤشر والسياق التاريخي محفوظان |
| M11 | بيانات تاريخية غير كافية | لا أرقام مختلقة؛ حالة عدم كفاية واضحة |
| M12 | العربية/الإنجليزية ولوحة مفاتيح | أسماء محلية ومعرفات ثابتة وتجربة RTL قابلة للاستخدام |

لا مقارنة Velocity لفرق مختلفة كدرجة إنتاجية، ولا تجميع نقاط وساعات في مؤشر واحد بلا تعريف صالح.

## التقسيم على الخطة القائمة

- **10A:** نموذج الإعداد والإصدارات والقدرات والتحقق وسياسة التحويل وخطة التغيير.
- **12A:** اختيار الأسلوب والمعاينة والتهيئة والمشاهد؛ إظهار الخيارات التي يدعمها الخادم فعلياً فقط.
- **14A–15A:** المراحل وبوابات الاعتماد والتبعيات وخط الأساس والتخطيط الهجين متعدد المسارات.
- **23A:** تعريفات تقارير حسب القدرات والفترة التاريخية وعزل نطاقات التجميع.

تظل أرقام الخطوات العامة 01–28 كما هي؛ هذه حزم فرعية وليست دعوة لتجاوز اعتمادياتها.

## مراحل الإتاحة

1. Scrum/Kanban/Simple بعد 10 و12، وفق اكتمال كل قدرة واختبارات M01–M08 وM12 المنطبقة.
2. Waterfall/Hybrid بعد 14 و15 واختبارات بوابات الاعتماد والمسارات والتبعيات.
3. التقارير الكاملة بعد 23؛ قبلها تعرض فقط المقاييس التي تدعمها بيانات وتعاريف صحيحة.
4. Custom بعد إثبات مصفوفة توافق القدرات؛ لا يسمح بتكوين غير صالح لمجرد مرونة الواجهة.
